6. `def register(name: str, module_path: str) -> bool`:
   - Per D-06: `importlib.import_module(module_path)`. On ImportError/Exception, store entry with status="import_error", error=str(e)[:200], module=None, failure_count=0. Log. Return False.
   - Per D-05: Call `validate_agent_module(module)`. If not ok, store entry with status="invalid", errors=errors, module=None, failure_count=0. Log. Return False.
   - On success: store entry with module=module, preferred_role=module.PREFERRED_ROLE, status="healthy", failure_count=0, error=None. Log. Return True.
   - After successful registration, persist to REGISTRY_FILE: save_json(REGISTRY_FILE, _get_registry_snapshot()). The snapshot is the list form (no module objects -- just name/status/role/failures).

7. `def unregister(name: str) -> bool`:
   - Pop from _registry. If existed, persist snapshot. Return True/False.

8. `def dispatch(query: str) -> list`:
   - Per D-04, D-07: Iterate _registry. Skip entries where status != "healthy" or module is None.
   - For each: check `entry["module"].owns(query)`. If True:
     - try: `obs, recs = entry["module"].handle(query)`. Append `(name, obs, recs)` to results.
     - except Exception as e: increment failure_count. Log with action="handle_error", agent=name, error=str(e)[:200], failures=failure_count. Append `(name, None, [])`.
   - Return results list.

9. `def list_agents() -> list`:
   - Return list of dicts: `{"name": n, "status": e["status"], "preferred_role": e.get("preferred_role"), "failure_count": e["failure_count"]}` for each entry.

10. `def get_agent(name: str) -> dict|None`:
    - Return entry dict (without module object) or None if not found.

11. `def _get_registry_snapshot() -> dict`:
    - Return dict suitable for JSON: `{name: {"status": ..., "preferred_role": ..., "failure_count": ..., "error": ...} for name, entry in _registry.items()}`. Exclude "module" key (not serializable).

12. `def init_default_agents()`:
    - For each name, path in DEFAULT_AGENTS: call register(name, path). Log summary.
    - This is called lazily or explicitly by coordinator.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Agent module loading | Untrusted module code loaded via importlib at registration time |
| Agent handle() execution | Agent code may raise, hang, or return malformed data |
| State file writes | Multiple processes (cron, workers) may write agents_registry.json concurrently |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | agent_registry.register() | mitigate | Hardcoded DEFAULT_AGENTS allowlist -- no dynamic registration from external input. Only known module paths accepted. |
| T-05-02 | Denial of Service | agent_registry.dispatch() | mitigate | try/except per agent.handle() call (D-07). Failure counter tracks broken agents. Broken agent returns None, does not block others. |
| T-05-03 | Information Disclosure | agent_protocol.Observation.details | accept | Details dict is internal only -- never exposed to Telegram directly. Coordinator formats output before sending. Low risk. |
| T-05-04 | Tampering | REGISTRY_FILE concurrent writes | mitigate | Registry writes only on register/unregister (rare ops). Plan 02 adds locked_write_json for shared state. Registry caches in memory, writes are audit trail. |
| T-05-05 | Spoofing | validate_agent_module() | mitigate | Duck-type checks (owns, handle, PREFERRED_ROLE) validated at registration. PREFERRED_ROLE validated against VALID_ROLES allowlist. Invalid modules rejected. |
</threat_model>
