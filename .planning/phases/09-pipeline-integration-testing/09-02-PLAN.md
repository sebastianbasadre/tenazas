  <action>
Create `workspace/runtime/agent_metrics.py` as the single Phase 9 persistence seam for metrics. Do not start an HTTP server here.

Required design:
- Persist to a JSON file under `workspace/runtime/logs/` so `metrics_server.py` can poll it.
- Provide at least these write helpers:
  - `record_agent_result(agent: str, elapsed_seconds: float, outcome: str)`
  - `record_route_result(strategy: str, handled: bool, source: str | None = None)`
- Keep labels low-cardinality. Valid outcomes should be a bounded enum such as `ok`, `error`, `timeout`.
- Track enough aggregate state for export:
  - per-agent query totals
  - per-agent outcome totals
  - per-agent latency sum and last/average latency
  - coordinator route totals by strategy
  - coordinator fallback totals by source (`skill_executor`, `llm_needed`)
  - handled vs unhandled route totals
- Use existing repo-style JSON helpers and error isolation so telemetry writes never crash routing.

This helper is intentionally small and storage-only. It should not contain Prometheus types or Grafana concerns.
  </action>
